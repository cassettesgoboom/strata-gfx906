PRs [#11](https://github.com/cassettesgoboom/strata-gfx906/pull/11) and [#12](https://github.com/cassettesgoboom/strata-gfx906/pull/12) add an archived MI50 measurement table and a CPU-only AB/CD trace comparator. These changes do not integrate AB/CD into the runtime, establish GPU overlap or parity, or change the published image.

- **Build and smoke boundary:** this build did not reproduce the pinned historical benchmarked binary (`ae93901c79771ace15db52942523c25fc46dd6f0d6a3b43698b28e6071c472cb`). The separate [GPU smoke receipt](../../benchmarks/gfx906/receipts/2026-10-16-current-main-gpu-smoke.json) shows real short serial inference by the new binary on dual MI50: 146 generated tokens on a first request, then 130 on a continuation with 70 native reused prompt tokens; MTP accepted/offered totals were 173/208. The source-equivalent server and binary were mounted into the archived runtime image. No new image was published. These short requests do not establish sustained performance, batch AB/CD, or exact token/state parity; archived benchmark measurements below remain scoped to the pinned binary.
- **Archived throughput evidence:** the README table now records six cached multi-agent runs from the published image: P2 serial at ~96K (38.43 strict / 33.35 whole-wave tok/s) and ~152K (45.19 / 36.19); P3 serial at ~99K (52.46 / 41.67) and ~152K (47.37 / 35.93); P4 AB/CD opt-in at ~33K (67.10 / 55.73) and 102K (71.17 / 53.94). The P4 102K run emitted 512/512/512/473 tokens, with the fourth lane stopping naturally. Strict overlap is an SSE-derived estimate; different rows do not establish causal speedup. P2 at ~192K with cached histories and 65-token continuations is capacity evidence only. See [EVIDENCE.md](EVIDENCE.md) for the full table and caveats. All figures apply to the archived binary and public dual-MI50 32 GB / K8-V4 scope.
- **AB/CD comparator boundary:** PR #12 adds a CPU-only comparator and synthetic fixtures for serial-OFF versus AB/CD-ON native commit traces. It checks supplied trace fields and reports the earliest divergence; its output always has `runtime_parity_claim=false`. Synthetic equality is comparator-contract evidence only: the tool cannot authenticate trace capture or prove runtime token/state parity. No current-main AB/CD port or runtime parity validation is included.
- **Transaction lifecycle boundary:** PR #15 adds a host-side registry for two disjoint row slices, immutable slot/token/position snapshots, registry-bound handles, lifecycle transitions, accepted-prefix bounds, and drain-before-reuse, with negative CPU cases. The hosted workflow passes 42 Python CPU tests and the C++20 transaction test. This is scaffolding only: the registry is not wired into `Verifier` or the scheduler, and there is no GPU overlap, device completion/drain, runtime token parity, or recurrent-state parity proof.
- **Current source:** upstream v0.1.44.1 already includes gfx906, K8/V4, and serial batch-MTP paths; see [the dated upstream map](UPSTREAM-DELTA.md). The current-main-equivalent build has a short serial GPU smoke, but current main has not passed batch AB/CD or parity validation; archived binary results do not validate it. [Draft PR #4](https://github.com/cassettesgoboom/strata-gfx906/pull/4) preserves a privacy-adapted historical AB/CD source candidate against v0.1.41 for review only. PR #12 supplies a CPU trace comparison contract but does not port that candidate to current main, reproduce the archived executable, or pass runtime token/state parity.
